## 项目简介

**Yuki-Blog App**（应用显示名 **Yuki Blog**，Dart 包名 `yuki_blog_app`，应用 ID `com.yiyu14.yuki_blog_app`）是给软件2615 班写的班级应用，用 Flutter 开发，一套代码跑 Android / iOS / macOS / Windows / Web。当前已完成的核心模块是**动态课程表**——把博客上那套按周次自动推算、支持临时调课的课表搬到了 App 里。

## 动态课程表

- **周次自动推算**：以数据里的 `week1Monday` 为基准算出当前真实周次，默认落在「本周」，提供上一周 / 下一周 / 手动选周 / 回到本周，周次条同时显示该周周一至周日的日期区间，到边界周自动置灰。
- **六种调整类型**：换教室（room）、调课（move）、对调（swap）、停课（cancel）、临时新增（add）、提示（note），全部按周次生效，不影响基础课表。
- **格子状态与图例**：有课 / 非本周 / 新增 / 停课 / 晚自习 / 实践周各有配色，界面底部给出图例说明。
- **课程详情**：点击格子展开详情面板，再点同格或按 × 收起。
- **本周调整面板**：把本周所有调课集中列出，无调整时整块隐藏。这一块的文案是运行时用「课程名 + 调整说明」拼出来的，不是可标注的整段原文，也不像通知那样「少数几条值得看」——每一行本来就都是这周要处理的事，所以它**只走词表着色**，不再叠句子底纹与档位加粗。
- **通知区**：位于课表网格下方，按真实周次过滤、过期自动消失，标题与正文同款关键词高亮。
- **数据更新历**：底部多彩面板（彩虹渐变标题、8 色循环色条与日期徽章、最新一条高亮角标），读取与博客线同构的 `meta.changelog`；网络同步失败回退离线数据时置顶提醒「可能不是最新」。
- **长内容一律走高亮**：凡是「一段话」级别的信息型正文——通知、更新历、本周调整、课程详情里的调整说明——**全部**接入这套高亮，不留纯文本角落。能内联标注的走三档（必看 / 关注 / 一般），运行时拼出来的（如「课程名 + 调整说明」）只走词表着色。
- **重点词高亮**：通知、更新历、本周调整与课程详情说明共用一套高亮——① 划词连片（关键词连同相邻的楼栋号 / 房间号 / 周次 / 时间连成一片，如「强能楼502」「G1楼401机房」）；② 划线叠加（角色波浪线、楼宇 / 科目 / 事项实线或点线，动作实线、负面词虚线）。六类**只用颜色 + 同色划线**区分角色 / 楼宇 / 科目 / 事项 / 动作 / 负面动作，亮暗双主题各一套色板；关键词不套色块也不加粗，把视觉重量全部让给「人工标注的重点」。
- **语义重点度（人工标注）**：重点不写死、也不靠算法猜，而是**每次有新信息入库前，先把内容读一遍，逐条标出哪几段值得看**——数据里用内联标记表达：`{{…}}` 必看、`[[…]]` 关注、`((…))` 一般（显式压档）。标记跟着文字走，改文案不会错位，渲染前整段剥离不显示。三档呈现：**必看**句淡荧光底 + 句首竖条（并加粗被标注的那几段）、**关注**句只加粗标注片段、**一般**句不加粗也不铺底，只剩词表上色。这样「讲工具本身」的条目不会被误当成重要通知，而「14:30 到强能楼502 参加入党谈话」这类必须处理的会一眼跳出来。
- **高亮密度受控**：底色只留「必看」一档、加粗只留「人工标注」，标注本身也按「每条至多一处必看 + 一处关注」收紧——更新历 + 通知里被标注的字数占比约 24%（此前为 45%），一屏扫下来只有少数几处真正跳出来，其余保持安静。本周调整面板则整层关掉定档，只保留词表着色。
- **算法与词表的分工**：固定词表（角色 / 楼宇 / 科目 / 事项 / 动作 / 负面六类）只负责**配色**与划词连片，不再决定重点；锚点打分算法退为**兜底**——只在该段一个标注都没有时（未审阅内容）才接手判档。人工判断重要性、词表给颜色，各司其职；遇到运行时拼出来的、无法内联标注的文案，就直接去掉定档这一层。

## 应用内更新

App 启动时会静默查询 GitHub Releases 的最新版本，与本地版本做语义化比较（兼容 `v` 前缀与 `+build` 后缀）；有新版本则弹窗展示变更说明，并给出两条更新路径：**应用内下载**（带进度条，含百分比 / 已下载大小 / 实时速度 / 预计剩余时间，可随时取消）下载完成后**直接唤起系统安装器**；或**浏览器下载**跳转直链自行安装。设置页也提供手动检查入口，手动检查时无论有无更新都会给出结果反馈。

最新安装包见 [Releases](https://github.com/cixiy1/Yuki-Blog-App/releases/latest)。

## 数据同步：与博客同源

课表数据与博客线完全同源同格式，都是 `schedule-2615.json`，App 侧按优先级依次尝试三个地址：

1. `yiyu14.top` —— Cloudflare Pages 线上站点（首选）
2. `raw.githubusercontent.com` —— 仓库源
3. `cdn.jsdelivr.net` —— jsDelivr 镜像

任一成功即解析返回（单地址超时 8 秒）；三个全失败时回退到打包进 App 的本地 `assets/data/schedule-2615.json`，保证离线也能看课表。

页面只依赖 `TimetableRepository` 接口取数，换数据源不需要动 UI 和解析逻辑。实际效果：**调课改班时只改博客那份 JSON，App 下次打开自动同步，不用重新发版。**

## 技术栈

| 领域 | 选型 |
|---|---|
| 框架 | Flutter（Dart SDK ^3.13.5）+ Material 3 |
| 路由 | go_router（`ShellRoute` 包一层抽屉导航壳） |
| 网络 | http |
| 更新检查 | package_info_plus（读本地版本）+ GitHub Releases API + url_launcher |
| 更新下载 | http 流式下载（自研进度与取消）+ path_provider + open_filex（FileProvider 唤起系统安装器） |
| 构建分发 | GitHub Actions（打 `v*` tag 自动跑测试、构建 release APK 并发 Release） |
| 主题 | 亮/暗双主题跟随系统，课表状态色从 `ColorScheme` 派生 |

## 构建与分发

Android 安装包不走手动打包：给仓库打一个 `v*` 形式的 tag，GitHub Actions（`.github/workflows/release.yml`）会自动执行 `flutter pub get` → `flutter test` → `flutter build apk --release`，把产物重命名为 `yuki-blog-<tag>.apk` 并发布到 Releases。App 内更新检查就是读这个 Release 的最新 tag 与本地版本比较；有新版可**应用内下载**（下载到应用缓存后经 FileProvider 交给系统安装器，需系统首次授权「允许本应用安装应用」），也可选择跳转浏览器下载。
